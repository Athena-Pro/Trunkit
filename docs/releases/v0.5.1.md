# Trunkit 0.5.1 — test report fixes

A patch release for the defects found by an independent test of 0.5.0 through
the real MCP client path. That test found no wrong verdict on a well-formed
claim: every valid certificate verified, every tampered one was refuted with a
reason, and empty or malformed input came back `unverified`. These fixes make
the verdicts and errors around those cases say what they mean.

```sh
python3 -m pip install --upgrade "trunkit[muse]"
trunkit init   # re-applies the schema so cert.verify picks up the change below
```

## Behaviour changes

- **A missing claim is `unverified`, not `refuted`.** `cert.verify` returns
  `ok = NULL` with `not_found: true` for an unknown claim id, so "checked and
  false" is no longer confused with "never existed". `claim_verify`,
  `claim_check` and the CLI `verify` and `check` commands check that the claim
  exists before calling it, so they report correctly even before `trunkit init`
  re-applies the schema.
- **The MCP server is quiet by default.** It now logs at `WARNING`, which drops
  the `Processing request` line the SDK wrote on every call. That line went to
  stderr, but stdio clients forward server stderr into their own output.
  Set `FASTMCP_LOG_LEVEL=INFO` to restore it.

## Fixes

- `ledger_chain` explains a version 1 bundle: the exporting ledger has no
  hash-chain extension, so no chain evidence was ever recorded. The verdict
  stays `unverified` with `chain_ok: null`, and a top-level `reason` now says
  why. Version 2 exports from a ledger with the extension still carry and check
  the stored hashes.
- `trunkit generate --backend pure` can be re-run, or run again with a higher
  `--limit`, on a populated database. It no longer fails on `primes_pkey`.
- `automata_extremal` names the input it expects,
  `{dfa, weights, initial_weight, final_weights}`, and says when it was given a
  bare DFA.

## Validation and pipeline

Regression tests cover each fix: missing claims through SQL, the MCP tools and
the CLI; re-running and extending the pure generator; the version 1 chain
reason; and the weighted-automaton error. The change passed the full release
gate on its pull request and again on `main`: PostgreSQL integration tests,
Linux and Windows wheel smoke tests, container checks, and the Muse-like
Ubuntu 24.04 environment. Release tags must match the package version. The
pipeline publishes to PyPI, then creates the GitHub release with wheel and
source archives.

See [Muse setup](https://github.com/Athena-Pro/Trunkit/blob/v0.5.1/docs/MUSE_SETUP.md)
for installation.
