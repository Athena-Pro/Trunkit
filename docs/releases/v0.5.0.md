# Trunkit 0.5.0 — Muse support and verified Porter handoffs

Fresh agent environments can install Trunkit with its MCP SDK and bundled libpq,
use existing PostgreSQL instances without Docker, and complete a verified Porter
handoff over stdio.

```sh
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install --upgrade "trunkit[muse]"
# Set CALX_DSN and NERODE_DSN to separate PostgreSQL instances.
trunkit quickstart --no-docker
trunkit generate --limit 10000 --backend pure
```

## Muse compatibility

- New `[muse]` extra installs binary Psycopg and the supported `mcp>=1.30,<2` SDK.
  The base pure-Python dependency remains available for other platforms.
- Optional commitment and arithmetic JSON-string arguments work over real MCP
  stdio, including explicit empty interpretation objects.
- External database roles work without a hard-coded `trunk` role or inherited
  search path. Arithmetic probes and bundle replay work on fresh connections.
- Exports preserve original stored chain hashes when installed; legacy bundles
  with absent hash evidence report `unverified`. Empty exports use `[]`.

## Porter v2

- Certificate-bound immutable snapshots and per-key SHA-256 manifests.
- Bounded read-only manifest opens and selected payload retrieval.
- Directed receiver routing and atomic expiring claim leases with release.
- Certified carried-ledger decisions for the receiver's first action.
- Prior-session DFA health warnings, including dead time and oscillation.
- Five MCP tools: `porter_open`, `porter_close`, `porter_claim`, `porter_release`,
  and `porter_open_and_gate`; writes require `TRUNKIT_ALLOW_WRITE=1`.

Legacy v1 Precacher calls remain available. Signed envelope transport,
user authentication, capture adapters, search, and retention remain future work.

## Proof and packaging updates

This release also ships the finite combinatorial and automata certificate
interfaces, checked constructions, statement/witness binding, exactness fixes,
and the current provenance and lifecycle layers already present in source.
Wheel resources use explicit file mappings to exclude local Lean build trees.

## Validation and pipeline

Local verification: **1,497 passed, 3 skipped, 27 deselected** on Python 3.12 and
isolated PostgreSQL 17.9 instances. Clean installed-wheel stdio checks verified
all 28 tools, every affected JSON argument, live claim/bundle replay, and a full
Porter v2 handoff with tamper rejection, budgets, leases, health, and a blocked
first action.

Publishing is gated by PostgreSQL integration tests, Linux/Windows smoke tests,
container checks, and a Muse-like Ubuntu 24.04 environment with externally
managed Python, no Docker binary, no system libpq, and separate PostgreSQL 16
services. Release tags must match the package version. The pipeline publishes
to PyPI, then creates the GitHub release with wheel and source archives.

See [Muse setup](https://github.com/Athena-Pro/Trunkit/blob/v0.5.0/docs/MUSE_SETUP.md)
and [Porter protocol](https://github.com/Athena-Pro/Trunkit/blob/v0.5.0/docs/PORTER_PROTOCOL.md).
